# 如何使用这个知识库

## 1. 先从一个问题开始

不要从“我想多存点资料”开始，而要从一个具体问题开始。

好的入口问题：

- 这个事件到底发生了什么？
- 这次危机或繁荣背后的机制是什么？
- 在这种制度环境下，哪类资产表现好，哪类资产表现差？
- 当前环境和历史上哪个案例相似？
- 政策制定者做了什么，市场之后又如何反应？
- 这里面有什么可以用于风险控制或资产配置的经验？

示例问题：

- 1989 年日本资产泡沫破裂之前，房价、股市、信贷和政策之间是什么关系？
- 2008 年全球金融危机中，银行系统的问题是如何传导到实体经济的？
- 高通胀时期，股票、债券、现金和房地产分别承担什么风险？
- 美国某一轮加息周期和今天有哪些相似点，哪些不同点？

## 2. 选择正确的文件夹

每个文件夹只负责一种任务。

| 文件夹 | 什么时候使用 |
|---|---|
| [[首页]] | 查看入口、规则、流程和自动视图。 |
| `01_时间线/` | 写一个年代的导读。 |
| `02_事件/` | 写真实历史事件，放进对应年代的子目录。 |
| `03_模式/` | 从多个事件中提炼反复出现的过程。 |
| `04_主体/` | 为国家、公司、机构、人物或地理要冲建卡。 |
| `05_资产/` | 研究资产类别、商品和货币的表现。 |
| `06_概念/` | 定义可复用的机制或金融概念。 |
| `07_对比/` | 用同一组问题比较多个案例。 |
| `08_方法/` | 记录投资者的分析方法。 |
| `10_观点/` | 记录某人的一个主张。 |
| `20_我的/` | 写自己的思考、决策和复盘。 |
| `99_工具/` | 找模板、跑检查脚本、看入库队列。 |

快速判断：

```text
一件真实发生的事            → event（事件）
一个国家、公司、机构、人物   → entity（主体）
一类资产、一种商品或货币     → asset（资产）
反复发生的过程              → pattern（模式）
可以复用的机制              → concept（概念）
投资者的分析步骤            → method（方法）
几个案例放在一起比          → comparison（对比）
某人说的一个主张            → view（观点）
一期视频或一份 PDF 的原文    → source（来源）
```

## 3. 日常使用流程

用一个小循环来维护这个知识库：

```text
提出问题
→ 搜索已有笔记
→ 判断笔记类型
→ 使用对应模板
→ 先写事实
→ 写出机制链条
→ 链接相关笔记
→ 标记不确定性
→ 提炼可复用经验
```

### 第一步：先搜索

创建新笔记之前，先搜索：

- 事件名称。
- 国家或地区。
- 年代。
- 危机类型。
- 资产类别。
- 关键机制。
- 可对比的历史案例。

这样可以避免重复笔记。

### 第二步：使用正确模板

创建结构化笔记时，用 Obsidian 的「插入模板」命令，从 `99_工具/模板/` 里选：[[事件模板]]、[[主体模板]]、[[资产模板]]、[[概念模板]]、[[模式模板]]、[[对比模板]]、[[方法模板]]、[[观点模板]]。

### 第三步：区分事实和分析

先写事实，再写解释。

```text
事实：发生了什么，哪些内容可以找到来源
机制：一个变量如何影响另一个变量
解释：这些事实可能意味着什么
投资启发：可复用的经验，不是个性化投资建议
未解决问题：哪些内容还需要继续核查
```

### 第四步：把笔记连进图谱

每篇有用的笔记都应该接入图谱。

事件笔记要在 YAML 里写清它涉及的国家、公司和人物、资产、模式、概念和可对比事件，并在正文第一次有意义地提到它们时加链接。

反方向不用手写：打开一张国家卡或概念卡，反向链接面板和卡片底部的视图会自动列出提到它的事件和观点。链接的具体写法见 AGENTS.md 第 6 节。

## 4. 如何阅读这个知识库

主要有四种阅读方式：

| 阅读方式 | 用途 |
|---|---|
| 事件阅读 | 理解一个历史案例到底发生了什么。 |
| 机制阅读 | 沿着概念和模式，看它们如何出现在多个事件中。 |
| 资产阅读 | 研究股票、债券、房地产、汇率、商品和现金在不同环境中的表现。 |
| 对比阅读 | 比较不同案例，理解相似点、差异点和错误类比。 |
| 观点阅读 | 从一个人或一个标的出发，按时间看各方说过什么、后来怎样。 |

读一篇笔记时，要一直问：

- 哪些是事实？
- 哪些是解释？
- 哪些仍然不确定？
- 哪个机制可以复用？
- 什么条件变化会改变结论？
- 现在有没有类似的现实场景？

## 5. 一篇有用笔记的最低标准

一篇有用的笔记应该具备：

- YAML 头部属性。
- 清晰的 `type`。
- 一句话的 `summary`。
- 标准化标签。
- 简洁事实。
- 机制链条。
- 有意义的链接。
- 来源状态 `source_status`。
- 不确定性标记。
- 相关时提炼投资或风险启发。

如果一篇笔记还没有达到这个标准，就保持为：

```yaml
status: draft
source_status: unsourced
```

草稿可以存在，但不能把不确定内容写成确定结论。

## 6. 不要把这个库当成什么

不要把这个知识库当成：

- 随手剪藏夹。
- 通用百科。
- 日记。
- 鸡汤和励志空间。
- 预测机器。
- 单一来源的投资答案。

应该把它当成一个思考系统：

```text
历史
→ 机制
→ 对比
→ 判断
→ 纪律
```

## 7. 查一个标的，或者查一个人说过什么

- **查一个标的**：打开它的卡片（例如 `石油`、`中海油`），底部的「在历史里出现过的地方」和「各方怎么看它」会按时间列出相关事件和所有人的观点。
- **查一个主题**：打开 `10_观点/` 下对应的文件夹，例如「选股与仓位」；卡多的文件夹开头有一篇导览，先读它。
- **查一个人**：打开 [[观点.base|观点]] 视图，按说话人分组；或者打开他的人物卡，看他谈论过什么。
- **查预测**：打开 [[预测追踪.base|预测追踪]]，看哪些预测快到期、哪些已经验证。
- **看原话**：每张观点卡第一段就是他的一两句原话，下面写着出自哪一期；要看整篇，到 `99Z_等待入库文件/已入库/` 里找，`入库队列.md` 记着出处和文件的对应。
- **看他最核心的想法**：打开 [[观点.base|观点]] 视图的「反复讲的」，按讲过的次数排。
