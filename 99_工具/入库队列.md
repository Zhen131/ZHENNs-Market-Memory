# 入库队列

这份清单记录 `99Z_等待入库文件/` 中材料的处理顺序。

46 个 Markdown 文件合并为 35 个材料单元。同一场内容的摘要、完整版和原始转写只处理一次，避免同一个观点重复进入图谱。

## 怎么使用

- 每次只处理一个材料单元，完成后停下来，不自动开始下一项。
- 先读完整个材料包，再搜索现有图谱，决定是新建、补充还是合并节点。
- 按 AGENTS.md 第 4.1 节的门槛新建节点，但不限制关联维护的文件数量。新材料如果让已有事件、主体、资产、概念或模式的事实更完整，应同步更新；索引由视图自动生成，不用手改。
- 脑总（Mr. Brain）的判断拆成观点卡，每张抄一两句原话、用 `said_in` 写出处，按 AGENTS.md 第 8.2 节写清前因后果（样板是「任天堂是游戏机里的苹果」），入库时用 `check_quotes.py` 核对原话；他以前讲过的意思不建新卡，在老卡上加一次出现（AGENTS.md 第 8.3 节）。他引用的数字标「据脑总说，未核实」，世界层转述他的判断时链到对应观点卡。
- 默认只核验支撑结论的关键事实。当期价格、预测和临场判断保留时间与观点归属。
- 一个材料单元完成后，在这里勾选并记录出处、形成的笔记与 Git 提交号。原始文件移到 `99Z_等待入库文件/已入库/`（文件名不改，内容不改），并在这里写下「出处 → 存档文件」的对应；流程见 AGENTS.md 第 10.1 节。
- 每个材料单元单独创建一笔中文提交。
- 云端自动入库时（见 `99_工具/云端入库说明.md`），`- [~]` 表示某个云端会话正在做，`- [!]` 表示做不下去、卡住了，原因写在下面；要 Zhen 定的事记在 `99_工具/云端待拍板.md`。
