# 历史金融图谱

一个用于整理金融历史、经济机制、货币制度、地缘冲击、政策反应、资产表现，以及投资者判断的个人 Obsidian 知识库。

这个项目的目标不是收集所有历史资料，而是把重要事件、机制、资产行为、案例对比和值得追踪的观点沉淀成一个可以长期查询、复盘和继续生长的「市场记忆系统」。

> 项目简介：一个用于整理金融历史、危机机制、资产表现和可复用市场判断的个人知识库。

## 这个项目是什么

历史金融图谱关注这些问题：

- 重大金融事件到底发生了什么？
- 风险是如何通过信贷、杠杆、汇率、银行系统、资产价格和政策约束扩散的？
- 政府、央行、银行、企业、居民和国际机构分别如何反应？
- 股票、债券、房地产、汇率、黄金、商品和现金在不同制度环境下如何表现？
- 不同历史案例之间有哪些相似点，哪些类比又可能失效？
- 投资者在什么时候、基于什么前提做过什么判断，后来是否应验？
- 哪些历史经验可以转化为风险控制、资产保护和长期判断的框架？

它不是通用百科、新闻剪藏夹、预测机器，也不是个性化投资建议库。每篇笔记都应该服务于未来的市场理解和历史比较。

更准确地说，这是一个把「金融历史」转化为「可复用判断框架」的 Obsidian 知识库。它关心的不是孤立故事，而是历史事件背后的结构：

- 信贷如何扩张，又如何收缩。
- 杠杆如何放大繁荣，也如何放大崩塌。
- 货币制度如何约束政策选择。
- 银行、政府、央行、企业和居民的资产负债表如何相互影响。
- 资产价格如何在通胀、通缩、战争、危机和政策转向中重新定价。
- 历史类比在什么条件下有帮助，又在什么条件下会误导判断。

## 为什么建立这个项目

学习金融历史，不是为了背诵过去，而是为了在未来面对风险时有可调用的记忆。

市场上很多判断会被短期价格、新闻情绪和单一叙事牵引。这个知识库希望用更慢、更结构化的方式，把历史案例拆成事实、机制、政策、资产表现、社会影响和未解决问题。这样未来再遇到类似场景时，可以先问：

```text
现在处在什么制度环境？
关键变量正在怎么变化？
谁的资产负债表最脆弱？
政策还有多少空间？
市场价格已经反映了什么？
历史上有没有相似结构？
这次相同点和不同点分别是什么？
```

最终目标不是预测每一次涨跌，而是建立一种长期判断力：看懂历史如何重演，也看懂每一次「相似」背后的不同。

## 三层结构

| 层 | 目录 | 装什么 |
|---|---|---|
| 世界层 | `01`–`06` | 时间线、事件、模式、主体（国家、公司、机构、人物）、资产、概念 |
| 认知层 | `07`–`08` | 案例对比、投资者的分析方法 |
| 观点层 | `10` | 观点：一个个可以单独引用和验证的主张，每张带一两句原话 |
| 个人层 | `20` | 自己的思考、决策日志和复盘 |

核心规则：**看法听说话人的，数字标「他说的」。** 这个库眼下主要用来内化脑总的投资思想：他的看法、框架和方法照原意记下，不加评判；他引用的史实和数字照写，但标明「据脑总说，未核实」，需要时再核实。他反复讲的同一个想法只有一张卡，每讲一次在卡上记一笔；预测卡到期后记录是否应验。

## 笔记类型

`event`、`entity` 等英文值只用于 YAML 查询；读者看到的文件名、标题和节点名都用中文。

| 类型 | 说明 |
|---|---|
| `event` | 真实历史事件，例如金融危机、资产泡沫、货币制度变化、战争冲击。 |
| `entity` | 具体对象：国家或地区、公司、机构、人物、地理要冲。 |
| `asset` | 资产类别、商品或货币，例如股票、债券、黄金、石油、美元。 |
| `concept` | 可复用的解释工具，例如杠杆、流动性、金本位制。 |
| `pattern` | 多个事件中反复出现的过程，例如资产泡沫、战时财政扩张。 |
| `comparison` | 不同案例之间的结构化比较，用来识别相似点、差异点和错误类比。 |
| `method` | 投资者的分析方法，写明谁提出、适用于什么、何时失效。 |
| `view` | 某人的一个主张：框架、判断、预测、操作或案例，带一两句原话和出处。 |
| `timeline` | 年代导读，不替代事件笔记。 |

## 写作原则

- 中文阅读优先。能用自然中文说清楚时，不写成英文串。
- 机制优先于故事。
- 别人的观点单独成卡，他引用的数字标明「据他说」。
- 一个对象只有一张卡；别名写进 `aliases`。
- 关系字段写成链接，只写在更具体的一方。
- 来源状态和不确定性必须明确标记。
- 投资启发必须来自历史机制和风险经验，不写成确定预测。

## 一份材料怎样入库

一个历史事件：

```text
提出问题 → 搜索已有笔记 → 选模板 → 写事实和机制
→ 链接国家、资产、概念、模式和可对比事件 → 标记来源和不确定性 → 运行检查
```

一份投资者材料（视频、直播、PDF）：

```text
通读，列出主张、框架、方法和提到的对象
→ 观点卡：先按意思搜老卡，讲过的加一次出现，没讲过的才建新卡；抄一两句原话，按「任天堂是游戏机里的苹果」的样板写清前因后果，查网补当时的背景
→ 世界层：提到的事件、公司、国家先查已有卡，够门槛才建；他说的数字标「据他说」
→ 方法、概念与对比：提炼可复用的想法
→ 运行检查、核对原话 → 原文移进 已入库/ → 记入入库队列 → 一个单元一笔提交
```

完整规则见 [AGENTS.md](<AGENTS.md>)。

## 如何维护

新增内容时使用 `99_工具/模板/` 里的模板：事件、主体、资产、概念、模式、对比、方法、观点。

每次修改后，在 vault 根目录运行：

```bash
python3 99_工具/脚本/check.py
```

它检查断链、重名、别名冲突、必填字段、关系字段格式和观点卡的出处，提醒太长该拆的卡，并生成 `00_首页/视图/待建节点.md`。

## 公开仓库说明

这个仓库公开展示的是一个个人知识系统的骨架和逐步生长过程。它更像一个长期研究工作台，而不是已经完成的教材。

观点卡里引用的视频与直播原话版权归原作者所有，这里只摘录一两句，用于个人学习和研究引用。原文存档放在 `99Z_等待入库文件/已入库/`，不出现在 Obsidian 的搜索和图谱里；但它们在 git 仓库里，仓库公开时别人也能看到。

如果你也在构建自己的金融历史知识库，可以参考这里的几个设计原则：

- 先建立分层和规则，再逐步填充内容。
- 把事实、观点和自己的判断分开存放。
- 每次新增内容时，都让它和已有节点产生关系。
- 让脚本检查规则，让视图生成清单，人只负责判断。
- 保留不确定性，不把草稿写成结论。
